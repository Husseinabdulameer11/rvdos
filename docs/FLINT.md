# Flint

Flint is the programming language built into RVDOS. You write programs with
`ED`, save them as `NAME.FLT` on drive A:, and run them by typing their name
at the `A>` prompt. The interpreter is a transient in ROM, like `PONG`, and
its parser is generated by [gram](https://github.com/Husseinabdulameer11/gram)
from [`flint.gram`](../os/flint.gram).

```
A>ED STARS.FLT          write it (ESC, X saves and exits)
A>STARS                 run it  (same as FLINT STARS.FLT)
A>FLINT                 interactive prompt: statements run as you type them
```

## A taste

```
# guess.flt -- guess the number
var secret = rnd(100) + 1
var tries = 0
while true
  print "Your guess? ";
  var g = input()
  tries += 1
  if g < secret
    print "Higher!"
  elif g > secret
    print "Lower!"
  else
    print "Got it in ", tries, " tries."
    break
  end
end
```

## The language

**One statement per line.** Blocks open with a keyword and close with `end`.
Indentation is for people; `ED` does it for you. `#` starts a comment.

**Values** are 32-bit signed integers. `true` is 1, `false` is 0, and any
non-zero value counts as true. Numbers can be written `255`, `0xFF` or `'A'`
(the character code, 65; escapes `'\n' '\t' '\e' '\0' '\\' '\''`).

**Variables**

```
var x = 10              declare (and set); var alone sets 0
var a[100]              an array of 100 zeros, indexed 0..99
x = x + 1               assign; also += -= *= /= %=
a[3] += 5
len(a)                  100
```

At the top level every variable is global, and `var` is optional. Inside a
function a name is **local** if it's a parameter, declared with `var`, or a
`for` variable; any other name means the global. (These are Lua's rules.)

**Operators**, loosest to tightest:

| | |
|---|---|
| `or` | `a or b` is `a` if it's true, else `b` (stops early) |
| `and` | `a and b` is `a` if it's false, else `b` (stops early) |
| `== != < <= > >=` | give 1 or 0 |
| `\|` `^` `&` | bitwise or, xor, and |
| `<< >>` | shifts (`>>` keeps the sign) |
| `+ -` | |
| `* / %` | `/` and `%` truncate toward zero, like C |
| `-x` `~x` `not x` | prefix; they bind tightest |

`not` binds tightly, like C's `!`: write `not (a == b)`, not `not a == b`.

**Control flow**

```
if x > 0                while n > 0             for i = 1 to 10
  ...                     ...                     ...
elif x < 0              end                     end
  ...
else                                            for i = 10 to 0 step -2
  ...                                             ...
end                                             end
```

`break` leaves the innermost loop, `continue` starts its next round. A `for`
loop's limit and step are worked out once, at the start.

**Functions**

```
func fib(n)
  if n < 2
    return n
  end
  return fib(n - 1) + fib(n - 2)
end

print fib(20)
```

Define functions at the top level, before or after their callers. Every call
gives a value; a function that ends without `return` gives 0. Arrays are
passed by reference. Recursion works up to 32 calls deep.

**Printing**

```
print "x = ", x         items are printed next to each other
print "no newline";     a trailing ; keeps the cursor on the line
print                   just a newline
```

Strings exist only as `print` literals (`\n \t \" \\` work inside them).
For text built at run time, print characters with `putch(code)`.

## Built-in functions

| | |
|---|---|
| `key()` | key waiting, or 0. Doesn't wait |
| `getkey()` | wait for a key, give its code |
| `input()` | read a line, give the number in it |
| `rnd(n)` | random 0 .. n-1 (seeded by your typing rhythm) |
| `abs(x)` `min(a, b)` `max(a, b)` | |
| `len(array)` | number of elements |
| `cls()` | clear the screen |
| `at(col, row)` | move the cursor; 53 × 25 cells |
| `color(fg)` `color(fg, bg)` | text colours (palette indexes) |
| `putch(code)` | print one character |
| `fill(col, row, c)` | paint a whole cell, for block graphics |
| `pixel(x, y, c)` `getpixel(x, y)` | 320 × 200 pixels |
| `rect(x, y, w, h, c)` | filled rectangle, clipped to the screen |
| `palette(i, 0xRRGGBB)` | change a colour; 0–3 are the console's |
| `wait(ms)` | pause (calibrated in the emulator at 25 MHz) |

`^C` stops any program, even in an endless loop or while it waits for a key.

## The interactive prompt

`FLINT` on its own gives a `flint>` prompt. Each statement runs as soon as
it's complete. A block waits for its `end` (`...` prompt), so you can define
functions there too. Variables, arrays and functions stay until `bye`. A bare
expression or a call prints its value, so the prompt is also a calculator:

```
flint> 7 * 6
42
flint> func sq(n)
...      return n * n
...    end
flint> sq(12)
144
```

## Errors

Mistakes are reported with the line number. Syntax errors also show the line
with a caret:

```
Error in line 2: syntax error, expected a value
  x = (3 +
          ^
Error in line 9: syntax error, expected '(', '[' or an operator (== compares)
  if x = 3
       ^
Error in line 34: index out of range
Error in line 3: division by zero
```

A whole file is compiled before any of it runs, so a syntax error anywhere
means nothing has happened yet.

## Limits

These come from the 32 KB machine. Everything lives in the TPA, the RAM the
OS lends to the program that's running:

| | |
|---|---|
| program | 4 KB of bytecode (roughly 250–300 lines) |
| names / strings | 768 / 1,024 bytes of text |
| globals | 128 · functions 40 · locals per function 32 |
| arrays | ~1,460 numbers in all when running a file, ~440 at the prompt |
| nesting | 12 blocks deep, ~10 levels of parentheses, 32 calls deep |
| line length | 160 characters |

Arrays declared inside a function are freed when it returns. Declare big
arrays once, at the top level: a `var a[n]` inside a loop allocates every
time round.

Speed: about 20,000 simple loop rounds a second on the 25 MHz core. The
Mandelbrot sample draws 4,000 points in about 3 seconds.

## How it's built

- **Parsing, one line at a time.** `flint.gram` describes one line, not a
  whole program. Each line goes through `gram_parse` with the precompiled
  tables (`gramgen flint.gram flint gen`). The tree is compiled and thrown
  away, so the parser never needs more than about 3 KB.
- **Blocks across lines.** The compiler keeps a stack of open blocks. When it
  sees `end` it patches the forward jumps. Several `break`s, or the
  `elif`/`else` exits, form a chain threaded through the jump operands
  themselves, so no extra memory is needed.
- **Expressions are a flat chain** in the grammar, `unary (binop unary)*`.
  The compiler applies precedence (precedence climbing). gram's parser
  recurses on the C stack at about 110 bytes per rule level, so one rule
  instead of eleven per `(` matters on a 6 KB stack. `GRAM_MAX_DEPTH=40`
  then makes too-deep input a clean error instead of a stack overflow.
- **A stack VM** runs the bytecode. Division goes through `sdiv32` in
  `mini.c` because the CPU has multiply but no divide. Every 1,024
  instructions it asks the OS whether `^C` was pressed.
- **Memory.** One struct at the bottom of the TPA, arrays above it, the gram
  arena at the very top. When a file has finished compiling, the arena's
  4 KB is handed to the arrays.

## Testing

```
tests/run_flint_tests.sh     # every tests/flint/*.FLT against its .OUT
```

Each test boots RVDOS in the headless emulator with the program on drive A:,
runs it, and compares the screen text with the expected output.
